## Verification plan (replacement)

### Abstract model

Let `O` be the total set of outcomes that `<SYM>@B` permits at the repository
boundary: returned values, returned failures, documented exclusions, and
documented panics or termination. Let `R` be the repository's mapping from each
`o` in `O` to an observable repository outcome. The preconditions are those
that `<SYM>@B` documents for its callers. The expected result is that every
`o` in `O` maps to exactly one documented `R(o)`, with no panic, unwrap, silent
discard, or unreachable branch introduced by repository code. A malformed input
that revision B rejects before `<SYM>` is outside `O`; verify the rejection at
the boundary that owns it.

The old model assumed an outcome `<FAILURE>` in `O_A`. Revision B removes it or
makes it unreachable, so `O_B` is the model of record.

### Invariants and lemmas

- `INV-ERRMAP`: for every outcome permitted by `<SYM>@B`, repository logic
  produces exactly one documented outcome and never panics, unwraps, or
  discards the result silently. Linked requirement: `<TDD-REQ>`.
- `INV-NO-DEAD`: no production branch, test, or acceptance claim targets a
  state that `<SYM>@B` cannot produce. Linked obligation: `<VO-FAIL>`
  disposition.
- `INV-ATOMIC`: every caller of `<SYM>` is updated to the revision-B contract in
  the same coherent change; no old and new outcome interfaces coexist. Linked
  requirement: `<TDD-REQ>`.
- `L-FAIL-REACH`: if `O_B` contains any failure outcome, or if the requirement
  is re-sourced at another boundary, at least one permitted witness reaches the
  corresponding failure handling. If neither case applies, the failure
  obligation is absent, not discharged by a vacuous test.

### Axioms (trusted, not verified here)

- `AXIOM-DEP-B`: the documented contract of `<SYM>@B` is the total outcome set
  `O_B`, including any guarantee that `<FAILURE>` cannot be produced. Source:
  `<provider document or contract path>@<immutable revision B>`, inspected
  `<date>`. Boundary: `<repository call site or adapter>`. The plan does not
  verify the provider's internals. Repository-owned mapping and error handling
  are verified against the real interface or a faithful contract-level
  boundary. A mock must not assume the disputed guarantee.
- `AXIOM-TOOLCHAIN`: the repository's compiler and lint configuration reports
  unreachable patterns or dead code when configured to do so. Source:
  `<configuration path>@<revision>`. If this axiom does not hold, compensate
  with an explicit enumeration or search and record the residual gap.

### Methods per obligation

- Obligation: `VO-ERRMAP`, discharge `INV-ERRMAP`.
  Method: exhaustive type match or enumeration where the language supports it;
  otherwise a parameterized contract-table test over every permitted outcome
  class.
  Rationale: the outcome set is finite and explicitly enumerated, so a
  parameterized check covers the partition directly.
  Domain: every `o` in `O_B`, including the no-failure case and any new
  revision-B failure class.
  Artefact: `<repository-relative test path>`.
  Evidence: focused command `<command>`; expected initial failure `<specific
  missing or wrong mapping>`; discharge condition `<all classes pass>`.
  Non-vacuity: exhibit one witness per class; seed a deliberate mis-mapping in a
  scratch change and show the check rejects it for the intended reason; revert
  the fault and remove generated artefacts. If a generated test is used, record
  generator acceptance and classification: a generator that filters out every
  failure case is a verification failure, not a pass.
- Obligation: `VO-FAIL-B`, conditional on `O_B` containing a failure outcome.
  Method: parameterized or property test at the real boundary, or a faithful
  contract-level boundary that does not assert the disputed guarantee.
  Rationale: a reachable failure path must be exercised with a permitted input,
  not with an impossible one.
  Domain: the permitted failure classes of `O_B`.
  Artefact: `<repository-relative test path>`.
  Evidence: focused command `<command>`; expected red before implementation and
  green after; discharge condition `<every permitted failure class handled>`.
  Non-vacuity: a witness that reaches the branch, plus a negative control that
  the check rejects when the branch is removed or mis-mapped. If a generator is
  used, record acceptance and classification evidence for every permitted
  failure class.
- Obligation: `VO-NO-DEAD`, discharge `INV-NO-DEAD`.
  Method: compiler or linter check with unreachable-pattern and dead-code
  reporting enabled for the affected crate, plus a review of every removed or
  retained branch.
  Rationale: the compiler proves the branch cannot execute only when the type
  system enforces the exclusion; a search alone does not.
  Domain: the affected crate and every caller.
  Artefact: `<gate command or lint configuration>`.
  Evidence: gate output shows no unreachable branch and no suppression
  attribute; a seeded unreachable arm is rejected as the negative control, then
  reverted.
  Non-vacuity: the seeded control demonstrates that the gate can detect the
  condition.
- Obligation: `VO-ATOMIC`, discharge `INV-ATOMIC`.
  Method: repository-wide search plus compile of the workspace.
  Rationale: a successful compile of the owning crate does not prove that an
  out-of-tree caller or feature-gated path was updated.
  Domain: all callers, examples, tests, benches, and feature combinations.
  Artefact: `<search command and workspace test command>`.
  Evidence: no revision-A outcome usage remains; all targets compile.
  Non-vacuity: the search must find at least one known caller before the change
  and none after; record the pre-change witness.
- Obligation: `<VO-FAIL>`, the revision-A failure obligation.
  Status: WITHDRAWN as acceptance evidence, not passed.
  Reason: `<FAILURE>` is unreachable under revision B by classification
  `<R1–R4>`; `<test-old>` cannot enter the branch.
  Replacement: `VO-ERRMAP`, plus `VO-FAIL-B` if a permitted failure remains, or
  the re-sourced obligation if Option B is accepted. Acceptance to retire or
  re-source: `<decision reference>`, pending.

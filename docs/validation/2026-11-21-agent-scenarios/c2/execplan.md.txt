## Purpose / big picture

The repository exposes a helper solely to its tests. After this change, the
helper has the narrowest surface its test callers can use, every test caller
uses that surface, and the old general-purpose exposure is gone. A maintainer
can observe success by running the repository's test suite and by searching
for the old helper surface: the tests pass and the search finds nothing. The
diff contains no alias, deprecated entrypoint, facade, adapter, dual
implementation, or temporary wrapper.

The compatibility shim suggested in the prompt is deliberately not built.
A shim would preserve the obsolete test-only interface, which the installed
contracts prohibit. If the requester makes the shim mandatory, this plan
enters `BLOCKED` until the demand is withdrawn or the surface is reclassified
with evidence.

Terms used here:

- **Helper** – the repository function, type, or module-level item whose only
  consumer is the repository's own test suite.
- **Test caller** – any test, doctest, example, benchmark, fixture, or build
  script reference to the helper.
- **Test-only API** – an interface or support surface whose sole purpose is
  to serve tests.
- **Compatibility shim** – an alias, deprecated entrypoint, facade, adapter,
  dual implementation, or wrapper that keeps an obsolete source interface
  usable.
- **Coherent plateau** – a repository state that is correct and internally
  consistent, not one that keeps old and new interfaces alive together.

Illustrative shape only; the symbols are not repository facts:

```plaintext
Before: tests -> old exposed helper
After:  tests -> reshaped helper
Never:  tests -> old alias -> reshaped helper
```

The helper's observable behaviour and the tests' assertions are preserved.
Deliberately changed: the helper's location, visibility, or signature, and
the test call sites. No error or diagnostic change is expected; if the
reshape would change one, that is a behavioural change requiring separate
acceptance.

## Constraints

- The helper definition and every affected caller change in one coherent
  commit. No partial migration is committed, and no intermediate state is
  required to build or test.
- No source-API compatibility machinery for this test-only surface. This
  prohibits aliases, deprecated entrypoints, facades, adapters, dual
  implementations, feature flags selecting old and new paths, and temporary
  wrappers.
- No production or public API change. If reconnaissance finds a production
  caller or a genuine external consumer, stop and reassess; the surface is
  no longer test-only.
- Test intent is preserved. Call sites may be rewritten. Assertions are not
  deleted, weakened, or marked expected-failure without a recorded
  disposition and, for behavioural changes, explicit acceptance.
- The helper's behaviour does not change unless separately requested and
  accepted.
- No new dependency, generated code, or unrelated cleanup.
- Repository guidance, including `AGENTS.md` and its gate targets, governs
  once inspected. Until then, no command is asserted as the repository's
  gate.
- Paths and modules that must not be modified: unknown until `EP-M0`. The
  default is that only the helper's definition and its test callers change.
- Historical documents, completed ExecPlans, and changelog history remain
  untouched.
- Implementation begins only after the user explicitly approves this plan,
  unless existing standing instructions already authorize execution. This
  draft does not authorize any repository change.

If satisfying the objective requires violating a constraint, do not proceed.
Record the conflict in `Decision log` and escalate.

## Risks

- Risk: the brief's "solely to its tests" is wrong and a production or
  external consumer exists.
  Severity: high. Likelihood: medium. Mitigation: `EP-M0` inventories every
  reference class before any edit; a non-test caller sets the plan to
  `BLOCKED`.
- Risk: a hidden caller in a doctest, example, benchmark, fixture, or build
  script is missed.
  Severity: medium. Likelihood: high. Mitigation: search every tracked file
  and classify each reference; compile and run the affected harnesses.
- Risk: the helper is exported by a released package and has genuine external
  consumers.
  Severity: medium. Likelihood: low, given the brief. Mitigation: inspect
  release lineage at `EP-M0`; if the surface is not test-only, reassess
  separately. A released test-only surface remains excluded from source
  compatibility.
- Risk: tests are rewritten to pass rather than migrated, losing coverage.
  Severity: high. Likelihood: medium. Mitigation: per-test review table,
  assertion diff review, focused suites, and a mutation negative control.
- Risk: the repository's gates are unavailable or already failing.
  Severity: medium. Likelihood: medium. Mitigation: record the baseline before
  editing, keep gate logs, and distinguish pre-existing failures from
  regressions.
- Risk: scope creeps into general cleanup of the helper's module.
  Severity: medium. Likelihood: medium. Mitigation: the tolerances and the
  one-helper scope; unrelated improvements become separate proposals.

## Verification plan

### Abstract model

A reference is a use of the helper through the old surface or the target
surface in a tracked file. Each reference has one state: definition, test
caller, production caller, or documentation reference. The transition
migrates every test caller and removes the old surface in one change. The
precondition is that every reference is a test caller; it is assumed by the
brief and must be established by `EP-M0`. A production, external, or
unclassifiable reference violates the precondition and stops the work.

### Invariants and lemmas

- `INV-001` – After the change, no tracked, non-historical file refers to the
  old helper surface. Links: `REQ-caller-completeness`.
- `INV-002` – Every baseline test caller exists in the target and reaches the
  reshaped helper. Links: `REQ-caller-completeness`, `REQ-test-intent`.
- `INV-003` – The change introduces no alias, deprecated entrypoint, facade,
  adapter, dual implementation, or temporary wrapper. Links:
  `REQ-no-shim`.
- `INV-004` – Every migrated test preserves its asserted behaviour. Links:
  `REQ-test-intent`.
- `L-001` – If `INV-001` to `INV-004` hold and the gates pass, the change is
  atomic and no compatibility obligation applies. Links: `REQ-atomic-reshape`,
  `REQ-no-shim`.

### Axioms (trusted, not verified here)

- `AXIOM-001` – The selected language mechanism restricts access as its
  documentation states. Source: language documentation, to be cited at
  `EP-M0`. Boundary: the helper's exposure.
- `AXIOM-002` – The repository test runner executes the migrated tests and
  reports them individually. Source: repository test configuration, to be
  inspected at `EP-M0`. Boundary: acceptance evidence.
- `AXIOM-003` – The repository's documented gates are the acceptance
  authority. Source: repository guidance, to be read at `EP-M0`. Boundary:
  `TOR-SUCCESS-002`.

The premise that the helper is test-only is not an axiom. It is
`TOR-ASSUMPTION-001` with an evidence obligation in `EP-M0`.

### Methods per obligation

- Obligation: `INV-001`, no old-surface reference remains.
  Method: repository-wide symbol search over tracked files plus diff review.
  Rationale: a search directly observes the claim and is cheap; the diff
  review catches renames that evade a literal search.
  Domain: every tracked, non-generated, non-historical file.
  Artefact: search transcript and target-symbol list in `Artefacts and notes`.
  Evidence: pre-change search finds at least one reference (proving the search
  can match); post-change search finds none outside historical records. The
  red stage begins with a migrated caller that cannot resolve the target
  symbol.
  Non-vacuity: seed an alias for the old name in a scratch, uncommitted edit
  and confirm the search reports it; revert the edit and confirm the search
  is clean.
- Obligation: `INV-002`, caller completeness.
  Method: baseline-to-target reconciliation plus compile and focused tests.
  Rationale: the inventory is finite and enumerable once known; compilation
  catches unresolved calls.
  Domain: every caller class recorded at `EP-M0`.
  Artefact: per-test review table.
  Evidence: every baseline caller has a target counterpart; the focused suite
  passes; the red stage fails for the intended missing-symbol reason.
  Non-vacuity: omit one caller migration in a scratch edit and confirm the
  build or search fails; revert the edit.
- Obligation: `INV-003`, no compatibility machinery.
  Method: diff review plus targeted search for shim forms.
  Rationale: no search can enumerate every shim shape, so human review of the
  complete diff is primary and the search is a backstop.
  Domain: the whole diff, including test-support modules.
  Artefact: diff and search output.
  Evidence: no added alias, deprecation marker, forwarding facade, adapter,
  or dual path.
  Non-vacuity: introduce one alias in a scratch edit and confirm both review
  and search reject it; revert the edit.
- Obligation: `INV-004`, asserted behaviour preserved.
  Method: per-test assertion diff review plus focused suites.
  Rationale: the risk is silent weakening, which a green suite cannot detect.
  Domain: every modified test.
  Artefact: per-test review table with "assertion change: none" or the
  accepted change and its authorization.
  Evidence: no assertion deleted or loosened without recorded acceptance;
  focused tests pass.
  Non-vacuity: mutate one expected value in a scratch edit and confirm the
  test fails; revert the edit.
- Obligation: `L-001`, atomicity removes the compatibility need.
  Method: argument from `INV-001` to `INV-004` plus the complete caller
  inventory.
  Rationale: once no caller remains for the old surface, there is no consumer
  for a compatibility layer.
  Artefact: this plan and the review table.
  Evidence: all four invariants discharged in one coherent commit.
  Non-vacuity: the witness is the complete inventory, which contains at least
  one caller before the change; an empty inventory would falsify the premise
  and stop the work.
